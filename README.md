# Python Pytest Embedded Automation

ESP32 firmware tests over Serial or Wokwi RFC2217. The homework firmware intentionally contains defects; a failed test requires investigation before it is classified as a firmware bug.

## Original project and additions

The original project includes buggy ESP32 firmware, LED/PWM commands, a DHT22 on GPIO15, requirements, a Serial client, and baseline pytest tests.

Added: 13 parametrized device cases for PWM, unknown commands and RESET; explicit safe-state setup/cleanup; elapsed-time timeout checks; three transport unit cases; three controlled-temperature samples; an opt-in disconnected-sensor test; and TX/RX logging. The fixture calls RESET, explicitly sets LED OFF and PWM 0, checks STATUS, and repeats cleanup before closing the connection. RESET itself remains independently tested.

## 1. Install dependencies

From the project root in PowerShell:

```powershell
cd automation
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
New-Item -ItemType Directory -Force evidence | Out-Null
```

Run all remaining Python commands from `automation` with this environment activated. Commands in this README assume the same PowerShell session.

## 2. Start the device

### Wokwi

1. Open `homework_buggy` in VS Code with PlatformIO and Wokwi extensions installed.
2. Build the PlatformIO project (or run `pio run` in `homework_buggy` if the CLI is available).
3. Start the Wokwi simulation. Its `wokwi.toml` configures RFC2217 port 4000.
4. In the automation terminal:

```powershell
$env:DEVICE_PORT = 'rfc2217://localhost:4000'
```

Rebuild after changing `src/main.cpp`, then restart the simulation. PlatformIO uses `src/main.cpp`; if using an Arduino sketch workflow, use `sketch.ino` and rebuild that sketch instead.

### Physical ESP32

Build and upload the firmware, then set the actual port:

```powershell
$env:DEVICE_PORT = 'COM5'
```

Close any Serial Monitor using the same COM port. The project uses 115200 baud.

## 3. Normal full-suite run

Keep the DHT22 data connected to GPIO15. Clear optional sensor settings for a baseline run:

```powershell
Remove-Item Env:SENSOR_FAILURE_TEST -ErrorAction SilentlyContinue
Remove-Item Env:EXPECTED_TEMP_C -ErrorAction SilentlyContinue
python -m pytest -v
```

Controlled-temperature samples and the disconnected-sensor test are skipped by default. Without DEVICE_PORT, device tests are skipped; transport unit tests can still run. The current suite contains 34 cases: the original 33-case result predates the added disconnected-sensor test.

To include controlled-temperature samples, first confirm the sensor in Wokwi is actually set to 24.5 C:

```powershell
$env:EXPECTED_TEMP_C = '24.5'
python -m pytest -v
```

The disconnected-sensor case remains skipped. Do not enable it during a connected-sensor full-suite run.

### Save evidence

```powershell
python -m pytest -v --capture=tee-sys `
    -o log_file=evidence/full_serial.log `
    --junitxml=evidence/full.xml 2>&1 |
    Tee-Object -FilePath evidence/full.txt
```

TXT contains console output; XML contains structured results; the Serial log contains TX/RX. Without `-o log_file=...`, the configured default is `evidence_serial.log`. Use different filenames for later runs to retain earlier evidence. HTML reports are not automatically generated by this command.

## 4. Run individual checks

```powershell
# PWM boundaries and additional homework scenarios
python -m pytest tests/test_boundaries.py tests/test_homework_cases.py -v

# Unknown commands only (requirement 8)
python -m pytest tests/test_homework_cases.py -k unknown -v

# RESET checks only
python -m pytest tests/test_relay.py tests/test_homework_cases.py -k reset -v

# Real communication timeout: device required
python -m pytest tests/test_timeout.py -v

# Transport unit checks: device not required
python -m pytest tests/test_transport_unit.py -v

# Investigate invalid PWM with complete traceback
python -m pytest tests/test_homework_cases.py::test_invalid_pwm_preserves_safe_state -vv --tb=long
```

Use one test process per device. Restart the simulation before an isolated diagnostic run if delayed responses may still be pending.

## 5. Verify temperature and detect a fixed reading

The supplied `diagram.json` sets DHT22 (`dht`) to 24.5 C and 45% humidity. GET TEMP exposes temperature only.

### First point at 24.5 C

1. Stop the simulation.
2. Confirm the DHT22 attributes in `homework_buggy/diagram.json`:

```json
"attrs": {
  "temperature": "24.5",
  "humidity": "45"
}
```

3. Confirm its data connection is `esp:D15` to `dht:SDA`.
4. Restart the simulation, then run:

```powershell
Remove-Item Env:SENSOR_FAILURE_TEST -ErrorAction SilentlyContinue
$env:EXPECTED_TEMP_C = '24.5'
python -m pytest tests/test_sensor.py -v --capture=tee-sys `
    -o log_file=evidence/sensor_24_5_serial.log `
    --junitxml=evidence/sensor_24_5.xml 2>&1 |
    Tee-Object -FilePath evidence/sensor_24_5.txt
```

### Second point at 31 C

Stop the simulation, change the DHT22 temperature attribute to `"31"`, and restart. Alternatively, change the DHT22 temperature control in the running Wokwi UI and let the reading settle.

```powershell
$env:EXPECTED_TEMP_C = '31'
python -m pytest tests/test_sensor.py -v --capture=tee-sys `
    -o log_file=evidence/sensor_31_serial.log `
    --junitxml=evidence/sensor_31.xml 2>&1 |
    Tee-Object -FilePath evidence/sensor_31.txt
```

The test takes three samples, waiting 2.1 seconds before each read. Each must return OK and a finite number within +/-0.5 C of the controlled input. Constant zero fails at these inputs; a fixed 24.5 reading fails at 31 C. Zero itself is valid at an actual 0 C input.

Changing EXPECTED_TEMP_C does not change the sensor. Change the actual simulated stimulus too. Two simulated points demonstrate API response to simulated input; they do not prove physical sensor health. For a physical sensor, use a stable stimulus and an independent reference thermometer with an agreed tolerance.

### Restore normal temperature

Stop the simulation, restore the DHT22 attribute to 24.5, restart, and either set EXPECTED_TEMP_C to 24.5 or remove it to skip controlled-temperature samples.

## 6. Simulate sensor failure

This scenario intentionally disconnects the data signal. Run it separately from normal temperature tests.

1. Stop the simulation.
2. In `homework_buggy/diagram.json`, replace the connection:

```json
["esp:D15", "dht:SDA", "green", ["v0"]]
```

with:

```json
["esp:D13", "dht:SDA", "green", ["v0"]]
```

GPIO13 is unused in the supplied diagram. Firmware still reads GPIO15. Preserve the surrounding JSON commas; do not leave a trailing comma after the last array item.

3. Restart the simulation.
4. Run only the failure test:

```powershell
Remove-Item Env:EXPECTED_TEMP_C -ErrorAction SilentlyContinue
$env:SENSOR_FAILURE_TEST = '1'
python -m pytest tests/test_sensor_failure.py -v --capture=tee-sys `
    -o log_file=evidence/sensor_failure_serial.log `
    --junitxml=evidence/sensor_failure.xml 2>&1 |
    Tee-Object -FilePath evidence/sensor_failure.txt
```

Expected: valid JSON with `status=ERROR`, `code=SENSOR_UNAVAILABLE`, and no temperature field. A temperature, malformed JSON, or timeout fails this scenario and must be investigated. Set SENSOR_FAILURE_TEST only after disconnecting the data line; the variable does not modify Wokwi.

### Mandatory restoration

1. Stop the simulation.
2. Restore `esp:D13` to `esp:D15` in the DHT22 connection.
3. Restore the desired temperature (24.5 C for the baseline).
4. Restart the simulation.
5. Clear the failure flag:

```powershell
Remove-Item Env:SENSOR_FAILURE_TEST -ErrorAction SilentlyContinue
$env:EXPECTED_TEMP_C = '24.5'
```

The fixture resets LED/PWM only. It does not restore diagram wiring or sensor temperature. Record this scenario as Not Run until it has actually been executed.

## 7. Known findings and interpretation

- PWM 100 is rejected in the supplied firmware, violating requirement 5.
- RESET acknowledges success without restoring OFF/0, violating requirement 7.
- Successful GET TEMP omits its closing JSON brace, violating requirement 3. Temperature checks fail at JSON parsing until this is repaired. Save original evidence before a fix; rebuild/restart after modifying firmware.
- PING delays 1.2 seconds in the supplied source while the client timeout is 1 second. Agree a response-time requirement before assigning a firmware defect. Delayed replies may affect subsequent commands.
- INVALID_VALUE responses can pass while an additional state assertion fails. Verify the actual fixture and state immediately before the command; do not assume the rejected input changed the output.

Group repeated failures by cause. Record the firmware build ID, endpoint, test inputs, expected/actual results and evidence files. See `TEST_SUMMARY.md` for earlier analysis; its recorded 33-case result does not include the later sensor-failure case.
